## 每一章节怎样写、怎样改

### Title 与 Abstract

标题先表达对象与可识别贡献；项目名可帮助记忆，但不能替代科学内容。摘要按“任务与缺口—具体机制／结果—证据范围—意义”组织，不规定必须五句。理论摘要应说清保证针对的对象；基准摘要应说清数据覆盖和评测定义；系统摘要须区分局部 kernel 指标与端到端收益。避免把论文中的作者自述 novelty 原封不动当作已核验事实。

修改时逐句标记：背景、缺口、方法、证据、解释。删除无信息的赞美词，为结果补齐协议／比较对象；没有已测数字就不编数字。范围受限的结果不能在摘要扩成普遍能力。

### Introduction

开头尽快让读者知道研究对象。将“已有方法不够好”替换为一个可检验的具体障碍，例如注意力噪声、端点插帧的多解性、类别覆盖不均、数据技能偏置。动机图能提供诊断证据时才放在前面。

中段分别写清：观察到了什么；用什么机制解释；为何选择这个干预。三者不是同一强度的结论。提出方法后，用贡献点对应后文证据，而不是罗列“提出框架、做大量实验、达到最好”。论文类型不同，贡献可以是反例、定义、定理、数据资源或执行实现。

### Related Work 与 Preliminaries

Related Work 按与当前决策有关的技术轴组织，末句指出可核查差别：输入条件、假设、目标、训练数据、表示或算力。不要把相关工作全写成缺点。

Preliminaries 只放理解新贡献需要的符号、继承目标和假设。让原有公式与新增项可以辨认；已有技术的重新组合是否有贡献，要由问题和验证支持，不能靠重新命名。

### Method：每个模块都要能执行和验证

用下面的“模块契约”检查真实模块，不为填表额外发明模块：

| 要素 | 写作检查 |
|---|---|
| 目的与障碍 | 解决哪一项已经建立的问题？机制解释是已证还是假设？ |
| 输入与状态 | 张量／变量、形状或含义、条件来源；训练／推理是否都可用？ |
| 运算 | 关键公式与实际依赖顺序；并行、共享、复制、残差不能混写。 |
| 输出与接口 | 输出注入哪里，影响哪个预测／损失／后续步骤？ |
| 学习方式 | 哪些参数冻结、更新或阶段切换；新组件与继承组件分清。 |
| 验证 | 什么比较能排除替代解释？模块删除是否改变参数、数据或预算？ |

可用原创句式骨架：`To address [observed failure under protocol], we compute [operation] from [available inputs] and inject [output] into [location]. During [stage], [parameters] are updated while [others] remain fixed. We test this choice by [controlled comparison].` 按真实信息改写，不逐模块机械重复。

理论模块用“定义—假设—命题—直观解释—证明路线—边界”替代神经网络模块说明。定理成立条件必须保留；数据依赖界、oracle 界、经验曲线不能互相替代。证明受益于某因素，不自动推出任意实现都改善。

### Experiments / Analysis

将实验问题写在小节开头，再给协议、结果和有限解释。常见问题包括：总体效果怎样；对哪个因素有效；额外成本是多少；在哪些条件失效。先列资源／数据／输入条件，再比较。

- **架构**：区分公开模型横评与同训练条件比较；参数、FLOPs 和训练 token 不是同一个预算。
- **生成**：分别报告保真度、控制、时间一致性；不同指标冲突时解释取舍。真实轨迹／额外条件行单独标记。
- **基准**：先验证 judge 的一致性与成本，再使用它排名；任务不理解引发的“拒绝”不等于安全能力。
- **理论**：经验图验证具体推论或算法效果，不能充当定理证明；未测的递归／推广版本要明确。
- **数据与架构**：构造同架构换数据、同数据换架构；只有合并干预的实验就只能支持合并效果。

消融选择最有竞争力的替代机制。因素有相互作用时用交叉组合；Transfusion 的模态适配器 × 注意力方式是可参考的组织例，不要求所有项目做全因子实验。

### Limitations / Conclusion / Appendix

限制写在具体机制与协议上：缺失对应关系、底座能力、界的假设、任务覆盖、judge 误差等。结论回到实际验证过的主张；潜在应用和未来实验用将来／假设语气。

附录承接可复现细节、证明、更多条件、失败例与补充结果。正文需要的关键假设、公平性条件和主要负面结果不能仅靠附录隐藏。自动解析发现的章节长度包含附录时，不据此推荐正文页数。

## 与 问题驱动案例 合用

ICLR 样本提供多种论证类型；问题驱动案例 对可控视觉生成的“需求—模块—定性效果—对应消融”提供细节。先按科研贡献选主结构，再按视觉任务选择作者案例。理论或测量论文不强制变成多模块视觉框架。最后核对正文、公式、训练状态、图中箭头、caption 和消融讲的是同一个方法。
