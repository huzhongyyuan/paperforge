# CCF-A 研究、写作与审稿主线

这是 PaperForge 的默认论文路线，配合 [统一写作](integrated-writing.md)、[审稿检查](review-gates.md) 和现有会议案例使用。CCF-A 是会议分级，不是统一文体：按目标学科、会议、年份、track 和稿件类型组织内容。现有具体案例主要来自 ML/CV；ICLR 等相关会议资料可供比较，不据此宣称所有收录会议都属 CCF-A。

## 从研究材料确定中心论点

读取与请求相关的实现、配置、原始结果和草稿，说明三件事：解决哪个问题，已有方法在哪个可核实条件下受限，新增机制或发现由什么证据支持。方法代码说明“实现了什么”，实验结果说明“验证到什么范围”，两者不能互相代替。

用一句工作陈述联系问题、变化和证据，再选择篇章结构。贡献、证据明确时直接完成授权范围内的稿件；有多个实质不同的论点或缺失关键信息时指出具体待定项，继续完成不依赖它的部分。段落修改不要求重新盘点整个项目。

| 贡献类型 | 论证重点 | 关键验证 |
|---|---|---|
| 新方法或模块 | 哪个设计约束促成该操作，计算依赖是什么 | 公平基线、模块消融、替代解释、收益与成本 |
| 理论结果 | 假设、结论、适用域以及与已有结果的差异 | 推导／证明、边界与反例；实验不能代替证明 |
| 数据集或 benchmark | 目标能力、构造协议、标注／评分有效性 | 泄漏和重叠检查、代表性、可靠性及协议限制 |
| 系统或效率 | 系统边界、瓶颈、工作负载与资源条件 | 吞吐和延迟分别报告、相同条件比较、端到端开销 |
| 分析或经验发现 | 被检验的命题、测量方式与适用范围 | 对照、重复性、反例和敏感性分析 |

## 把贡献写成可审阅的连续论证

先列段落职责，再写实际正文。对已有章节做反向提纲：为每段写一句“这一段让读者理解什么”，核对它与章节问题、前后段和证据的关系。重复职责可合并；缺失推理补解释；没有材料支持的结论缩小或标出所需证据。

引言建立问题、已知不足、设计认识和贡献；方法按真实依赖说明动机、输入、操作、输出与训练／推理状态；实验围绕要回答的问题组织。相关工作按机制、假设、监督、成本或评价协议比较。段落开头帮助读者定位主张，后句提供解释、依据或必要转折。

写作指南里的五句摘要、贡献条数、方法出现页码和固定段数均是例子，不能作为统一验收标准。目标会议对页数、声明、匿名和 checklist 的要求要从当期官方文件核对，不从已录用论文或上游旧模板推断。第一张图选择能解释中心问题、机制或证据的内容，不给每篇论文强加 teaser。

## 让每项实验回答一个问题

在已有实验记录中对应 `主张 → 对照或检验 → 配置/数据划分 → 指标 → 原始结果 → 图表位置`。比较前核对训练数据、骨干、分辨率、调参预算和计算范围；差异真实存在时明确说明。消融改变了多个因素时，只能支持组合变化，不能单独归因于其中一个模块。

性能、机理、效率、泛化是不同主张，需要相应证据。只对当前材料支持的范围写结论；新实验方案标为计划，不把建议写成已验证收益。

## 从原结果核对论文数字

在修改涉及的范围内，直接读原始结果和配置，复算均值、样本数、差值及相对变化；完整投稿检查再覆盖全文数字。保留原始 Run 和失败记录，摘要／日志只能帮助定位来源。

| 容易写错的内容 | 核对方法 |
|---|---|
| 最佳 seed 被写成均值 | 核对实际重复次数、聚合方式与正文措辞 |
| 相对提升与百分点混淆 | 对齐基准、方向、分母及单位；改善幅度由实际公式复算 |
| 不同配置的结果混用 | 对齐数据版本、划分、模型、协议和产物版本 |
| 精度、表格和 caption 不同 | 从同一原值按展示精度舍入，再比对各处 |
| “所有／持续／全面”超过测试范围 | 查全部相关比较、失败和缺失项，缩小未获支持的量词 |

记录核对位置、原值与证据路径；区分匹配、合理舍入、配置不同、证据缺失和数值不符。计算检查与科学解释分别判断。独立审阅沿用项目已授权的 reviewer；此路线不自行启动新 Agent、模型或实验。

## 审稿与 rebuttal

按 [review gates](review-gates.md) 检查贡献、方法、实验和图文一致性。每条重要意见给位置、证据、影响与可执行修改；只修改用户请求的范围。rebuttal 对应审稿问题，区分澄清、事实更正、已有证据、实际新增实验和有依据的分歧，报告真实修改位置。

完成科学核对后做 [表达精简](anti-defensive-writing.md)。交付修改稿或源文件、实际验证和影响结论的缺口；不把文字顺畅或格式通过称为论文录用质量验收。
