# Anti-defensive：直接表达，保持证据与结论一致

适用于本 skill 生成或修改的论文正文、贡献、图注、讨论和 rebuttal。它是统一改稿流程中的语言环节；论证结构、证据和引用由同一流程的写作与 review 模块负责。简单修改在内部完成检查即可。

## 核心约束

优先说明任务、方法、发现和适用条件，删除没有新增信息的自我辩解。语气增强不能增加科学含义：不新增原材料没有的事实、数字、因果关系、优先权、泛化范围或领先程度。若另有已核实的证据支持事实修正，按事实修正处理并说明依据。

限制是否需要保留，取决于它是否改变当前主张的有效性、证据解释、研究设计或适用范围。影响当前句子的条件就近交代；其余协议细节集中说明，避免在每节反复道歉。不能用“限制只写一次”把摘要中的错误泛化留到附录补救。

## 改写顺序

1. **读上下文，判断功能。** 区分重复辩解、必要范围、真实方法限制、有效概念对比、证据限定和重复澄清。不要按词匹配删除。
2. **恢复段落主张和接口。** 用事实、机制或结果开篇。后句应解释或推进前句，下一段应承接尚未解决的问题。保留能说明模块必要性的转折。
3. **删冗余，或改成具体范围。** 将泛泛的“我们不能覆盖一切”换成实际数据、对象、条件和协议。没有这些事实时不补造；保留真实不确定性及其来源。
4. **把结论放回证据范围。** 区分测量、观察、解释和假设；核对比较对象、指标、样本划分以及训练／推理状态。首创、最强、普遍适用等表述仍须经过对应审计。
5. **比较改写前后的含义。** 核对数字、引用、符号、样本性质、因果力度、比较维度与归因。每个变强的谓语或量词都要有依据；删除限定后若会误导，恢复具体条件或缩小主张。

## 具体判断

| 类型 | 合适的处理 |
|---|---|
| 堆叠 might / could / potentially / merely attempt | 保留有实际根据的不确定性，用可核实的动作或观察代替重复缓冲。 |
| 重复 we do not claim / does not establish | 已有信息不再重复；需要保留的事实改为具体范围或协议。 |
| however / not / rather than / although | 没有禁词表。解释残留问题、区分方法或保持逻辑的对比应保留。 |
| competitive / promising / strong | 判断是否提供可核实信息。可直接陈述已支持的能力；不能改成 unsupported superiority。 |
| first / best / strongest / consistently outperforms | 检查原始文献、比较集合和结果维度；语气偏好不能代替优先权或比较审计。 |
| 抽样审计、共享场景、训练可见诊断、缺少消融 | 这些可能改变结论解释，按实际协议明确表达；不能包装成全量验证、独立泛化或因果归因。 |

摘要、引言、贡献和结论可突出中心结果，不要求逐项罗列所有指标；表格与结果分析仍须如实呈现相关比较。若主张覆盖多个共同主要指标，不能仅挑赢家而保留“全面优于”的结论。贡献陈述以已完成的产物、机制或发现落点，并提供适当的验证指向。

## PanoErase 类任务的应用示例

以下仅说明判断方式；实际参数与结果以当前项目源文件为准。

- 若实现确实只有一个推理生成器，可将 “inference does not run two successive removal models” 改为 “Inference uses a single generator.”，同时在方法中保留两阶段训练的说明。
- “Geometric continuity alone does not determine which visible content should disappear.” 解释几何重建之后的剩余问题，应该保留其论证作用。
- 对抽样质量检查，写明抽取了多少对、检查哪些帧和发现什么；不能把抽样协议改写成全库已经验证。
- 训练可见的真实视频诊断仍表述为 diagnostics；它不支持 held-out real-world generalization。
- 若证据支持效应移除和接缝一致性，就具体陈述这些收益；不能把保留区的 competitive 改成 superior，或推成全部指标领先。
- 对 EffectErase、SVOR、FastVMT 等相关工作保留准确引用、继承关系和具体区别。借鉴行文结构前核对原文；风格改写不能抹去方法来源。
